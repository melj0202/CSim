\section{Game domain and rulesets}
\label{sec:game}

\subsection{CellGameModule}
Primary gameplay module. Owns a \symbolref{CellContext} and an enum
\symbolref{CellState}:
\begin{center}
\texttt{NORMAL} $\mid$ \texttt{EDIT} $\mid$ \texttt{SAVE} $\mid$ \texttt{LOAD} $\mid$ \texttt{EXIT}
\end{center}

\begin{statusbox}
Mode handling is an \textbf{enum + switch} inside the module, not the older
class-per-state hierarchy (archived under \pathref{archive/old-states/}).
\texttt{E} toggles EDIT/NORMAL and wakes \symbolref{SplashText}.
SAVE/LOAD use Ctrl+S / Ctrl+O helpers; enum cases may still be thin.
Simulation rate: env \texttt{tps} $\times$ \texttt{speedFactor}, with
accumulator + step cap.
\end{statusbox}

\subsection{CellContext}
Constructs \symbolref{Canvas} from env vars (\texttt{CanvasX}, \texttt{CanvasY})
and selects a \symbolref{RuleSet} from a mode string
(\texttt{GAME\_OF\_LIFE}, \texttt{BRIANS\_BRAIN}, \texttt{SEEDS}, \ldots).
Mode changes from console/env call \texttt{setRuleSet} and
\texttt{Canvas::rebuildPalette}.

\subsection{Canvas (domain + view + GPU --- D-C1)}
\begin{itemize}
  \item CPU grid: \symbolref{lifeCanvas} (one byte per cell), dense rectangle
        (not chunked).
  \item View: CPU palette $\rightarrow$ \texttt{targetRgb}; \texttt{displayRgb}
        eases toward targets; \texttt{texCanvasBuffer} RGB bytes for upload.
  \item Token view: enrolled mesh/shader/display texture; dirty-rect
        \texttt{UpdateTexture} (PBO path).
  \item Dual role is intentional at current scale; split only if pure-sim tests
        or large grids require it.
\end{itemize}

\subsection{Scale walls (simulation / memory)}
\begin{statusbox}
\texttt{calcGeneration} always walks the \textbf{full} grid (rect args ignored).
Neighbor counts are scalar Moore/toroidal. Change detection does a second full
pass for a dirty AABB (good for sparse \emph{visual} updates, still $O(WH)$).
Per cell: 1\,B life + $\sim$24\,B float RGB + 3\,B display tex.
Default $80\times 60$ is fine; large/infinite canvases need a redesign (chunking,
bitboards, or dropping dual float fade).
\end{statusbox}

\subsection{Rulesets}
Active rules (in \pathref{AllSets.h} / factory): Game of Life, Seeds, Brian's
Brain, Highlife, Day \& Night, Life Without Death. Stub headers exist for
Rule 90 / 184 / Wireworld (identity \texttt{nextState}; not in AllSets).

\begin{lstlisting}
class RuleSet {
  // Pure transition: cell + Moore count of alive (value==0) neighbors.
  virtual unsigned char nextState(unsigned char cell,
                                  unsigned char aliveNeighbors) const;
  virtual void evalCell(const unsigned char& target,
                        unsigned char dest[3]) const; // palette colors
  void calcGeneration(...); // double-buffer: nextGen then memcpy
};
\end{lstlisting}

\textbf{Generation (perf):}
\begin{enumerate}
  \item Count-alive neighbors from raw \texttt{lifeCanvas} (toroidal, fast wrap).
  \item Write \texttt{nextState} into a scratch \texttt{nextGen} buffer.
  \item If any cell changed: \texttt{memcpy} back, mark sparse dirty AABB for
        visual/GPU upload. Still life: no dirty.
\end{enumerate}

\begin{decisionbox}[title={Keep rules pure}]
Rulesets stay free of rendering and input. They read/write cell buffers only
and expose \texttt{evalCell} for palette colors. That keeps them testable
(headless \texttt{TestRuleSets}).
\end{decisionbox}
