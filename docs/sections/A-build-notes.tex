\section{Build notes}
\label{sec:build}

\subsection{Configure \& build (Windows)}
\begin{lstlisting}[language={}]
cmake -S CSim -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
\end{lstlisting}

The default build compiles the application and \texttt{CSimTests}, then runs
the \texttt{CSimTests} CTest entry through the \texttt{CSimRunTests} target.
Use an explicit target only for a focused build.

\begin{lstlisting}[language={}]
cmake --build build --config Release --target CSimTests
\end{lstlisting}

Artifacts:
\begin{itemize}
  \item \pathref{build/Release/CSim.exe}
  \item \pathref{build/Debug/CSim.exe}
  \item \pathref{build/Release/CSimTests.exe} (legacy CMake target
        \texttt{CSimRenderTests} aliases \texttt{CSimTests})
\end{itemize}

\subsection{Tests (headless)}
\begin{lstlisting}[language={}]
ctest --test-dir build -C Release -R "^CSimTests$" --output-on-failure
# or: build/Release/CSimTests.exe
\end{lstlisting}
No OpenGL context is required (\texttt{MockBackend}).

\subsection{Known setup issues}
\begin{itemize}
  \item GLEW is pulled via \pathref{thirdparty/glew-2.1.0/build/cmake}; that
        subtree must exist (do not delete vendored CMake helpers).
  \item Debug may enable \texttt{/fsanitize=address}; requires a toolchain that
        supports MSVC ASan.
  \item FreeType may warn about missing optional system deps (HarfBuzz, zlib,
        PNG); build can still succeed with bundled defaults.
  \item GLSL under \pathref{CSim/Shader/} is copied to the build tree at
        configure time; after adding shaders, reconfigure or copy into
        \pathref{build/Shader/}.
\end{itemize}

\subsection{House style (CONTRIBUTING)}
See \pathref{CSim/CONTRIBUTING.md}: limited \texttt{auto}, avoid namespaces,
no recursion, third-party via PR.
