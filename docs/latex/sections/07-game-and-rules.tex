\section{Game domain and rulesets}
\label{sec:game}

\subsection{CellGameModule}
Primary gameplay module. Owns a \symbolref{CellContext} and an enum
\symbolref{CellState}:
\begin{center}
\texttt{NORMAL} $\mid$ \texttt{EDIT} $\mid$ \texttt{EXIT}
\end{center}

\begin{statusbox}
Mode handling is an \textbf{enum + switch} inside the module, not the older
class-per-state hierarchy (archived under \pathref{archive/old-states/}).
\texttt{E} toggles EDIT/NORMAL and wakes \symbolref{SplashText}.
Save/load, pause/run/step, canvas, ruleset, and camera behavior is exposed as
registered console commands rather than artificial frame states.
Simulation rate: env \texttt{tps} $\times$ \texttt{speedFactor}, with
accumulator + two-step cap; excess catch-up debt is dropped to keep input and
camera responsive. Status reports active chunks, stored and counted cells,
candidate and halo targets, worker count, the selected path, and steps completed
in the current frame. Painting and simulation operate on signed world coordinates;
there is no finite or toroidal production canvas.
\end{statusbox}

\subsection{Domain console commands and persistence}
\symbolref{CellGameModule} registers domain commands through
\symbolref{CommandRegistry}; Services remains free of Game types. Save always
writes version 2 sparse files with magic/version, ruleset, camera metadata, and
sorted 16$\times$16 chunk records. Load validates temporary state before
mutation, accepts both version 2 and the prior dense format, imports legacy
cells around the origin, restores ruleset/camera metadata, and snaps the
bounded view. Native picker variants route through the platform
\symbolref{SaveLoad} API. See D-CLI1 and
\cref{sec:session-2026-08-04}.

\subsection{CellContext}
Constructs \symbolref{SparseCellGrid} and bounded \symbolref{CanvasView} from
env vars (\texttt{CanvasX}, \texttt{CanvasY}) and selects a \symbolref{RuleSet}
from a mode string
(\texttt{GAME\_OF\_LIFE}, \texttt{BRIANS\_BRAIN}, \texttt{SEEDS}, \ldots).
Mode changes from console/env call \texttt{setRuleSet} and
\texttt{CanvasView::rebuildPalette}.

\subsection{SparseCellGrid (domain) and CanvasView (view --- D-C3)}
\begin{itemize}
  \item Domain: signed 64-bit cell addresses map through floor division into
        non-background 16$\times$16 byte chunks. Negative coordinates and all
        multi-state values are preserved; no fixed chunk pool cap exists.
  \item Simulation: each chunk carries a compact stored-cell occupancy mask and
        a separate neighbor-counting mask. If any source
        chunk has fewer than 48 counted cells, the grid creates exact affected
        targets through a retained generation-stamped
        open-addressed index. Its slots address contiguous scratch records
        containing a 256-bit candidate mask and 256 neighbor counts. It
        evaluates only non-background cells and neighbors of counted cells.
        Each target selects candidate or direct halo evaluation independently
        from its counted-neighbor contribution work; all-dense counted worlds
        bypass scratch construction. This keeps Wireworld conductors separate
        from the heads that actually contribute neighbor counts. Before either
        complete path, a retained changed-chunk frontier expands
        by one chunk in every direction. An empty frontier performs no cell
        evaluation; frontiers of at most 64 target chunks patch the retained
        prior-generation map directly. At 16,384 or more candidates, retained
        ranges of roughly 2,048 candidate cells use up to four automatic
        workers and independent result slots; smaller sets keep direct serial
        output. Denser worlds use deterministic direct
        18$\times$18 halo/core
        work; at 32 or more targets a reusable pool evaluates independent cores
        with up to eight workers. Both paths write into a retained inactive map
        using recycled node handles before transactional comparison/swap. Empty
        space is implicit and non-toroidal. The revision changes only when cell
        contents differ.
  \item View: \symbolref{CanvasView} samples contiguous 16$\times$16 cells
        around the camera, fades palette colors, and snaps newly revealed
        cells. At far zoom, its bounded active texture carries density-colored
        overview texels rather than one texel per source cell.
  \item GPU: one reusable nearest-filtered RGB display texture and one
        world-space \symbolref{GameVisual} quad that shares its cell bounds
        with the editor cursor; at most one dirty texture update per view
        submission.
  \item Dense \symbolref{CellGrid}/\symbolref{Canvas} remains only for
        compatibility tests and legacy import, not as a second runtime path.
\end{itemize}

\subsection{Scale walls (simulation / memory)}
\begin{statusbox}
Sparse simulation cost follows stored cells, counted cells, and their local
birth candidates, not a fixed world rectangle. Mixed targets independently use
candidates or chunk halos; 32 or more halo targets use up to eight reusable CPU
workers. A cached 256-state by 9-neighbor transition table serves every hot
loop, and dense halos use rolling three-row neighbor counts. Presentation samples only on grid/camera/palette changes
and limits far-zoom output to roughly one texel per four screen pixels. GPU
resources do not scale with chunk count.
\end{statusbox}

\subsection{Rulesets}
Active rules (in \pathref{AllSets.h} / factory): Game of Life, Seeds, Brian's
Brain, Highlife, Day \& Night, Life Without Death, Wireworld. Stub headers
remain for Rule 90 / 184 (identity \texttt{nextState}).

\begin{lstlisting}
class RuleSet {
  // Pure transition: cell + Moore count of alive (value==0) neighbors.
  virtual unsigned char nextState(unsigned char cell,
                                  unsigned char aliveNeighbors) const;
  virtual void evalCell(const unsigned char& target,
                        unsigned char dest[3]) const; // palette colors
  const TransitionTable& getTransitionTable() const;
};
\end{lstlisting}

\textbf{Generation:}
\begin{enumerate}
  \item If the retained changed frontier is empty, return immediately. If its
        one-chunk expansion contains at most 64 targets, evaluate those targets
        and transactionally patch the retained prior-generation map. Edits and
        ruleset-type changes repopulate the frontier; broad changes fall back
        to a complete path.
  \item Count stored and neighbor-counting cells from separate chunk masks for
        a complete path.
  \item If any source chunk is counting-sparse, create exact affected targets
        directly through the
        retained generation-stamped flat index, reset their contiguous
        masks/counts, mark non-background cells plus neighbors of counted cells,
        then choose candidate bits or a direct halo independently for each
        target from counted-neighbor contribution work. Large sets are divided
        into coarse work-count ranges for the reusable worker pool.
  \item If all source chunks are counting-dense, bypass candidate scratch and
        read nine neighbors into a temporary 18$\times$18 read-only halo for
        each target core. Reduce it through three rolling horizontal rows and
        evaluate serially or through the bounded worker pool for 32 or more targets.
  \item Install non-background results serially into the retained inactive map,
        reusing extracted chunk-node handles before allocating new nodes. Compare
        and swap transactionally only when contents differ.
\end{enumerate}

Before worker dispatch, the active ruleset lazily builds its 2,304-entry
transition table. Candidate, halo, and compatibility dense loops index this
immutable table rather than invoking virtual transitions for every cell.

\begin{decisionbox}[title={Keep rules pure}]
Rulesets stay free of rendering and input. They read/write cell buffers only
and expose \texttt{evalCell} for palette colors. That keeps them testable
(headless \texttt{TestRuleSets}).
\end{decisionbox}
